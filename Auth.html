ការយល់ដឹងពី Authentication និង Authorization
2. Understand
នៅក្នុងប្រព័ន្ធសុវត្ថិភាពទិន្នន័យ (Software Security) ពាក្យពីរម៉ាត់នេះតែងតែដើរទន្ទឹមគ្នា ប៉ុន្តែមានតួនាទី និងភារកិច្ចខុសគ្នាទាំងស្រុង ដែលអ្នកអភិវឌ្ឍន៍ប្រព័ន្ធចាំបាច់ត្រូវយល់ដឹងឱ្យច្បាស់៖
១. Authentication (AuthN) - "តើអ្នកជានរណា?" (Who are you?)

និយមន័យ៖ គឺជាដំណើរការ ផ្ទៀងផ្ទាត់អត្តសញ្ញាណ របស់អ្នកប្រើប្រាស់ (User Identity) ថាជាមនុស្សពិតប្រាកដដែលមានគណនីក្នុងប្រព័ន្ធ ឬអត់។ វាធ្វើឡើងតាមរយៈការផ្ទៀងផ្ទាត់ Email/Username និង Password, Biometrics, ឬ OTP Tokens។

ប្រយោជន៍សំខាន់ៗនៃ Authentication៖
  • ការពារប្រព័ន្ធមិនឱ្យជនចម្លែក (Anonymous Users) ចូលប្រើប្រាស់ផ្នែកអាថ៌កំបាំងបាន។
  • បង្កើតជា Digital Identity (Claims, User ID) សម្រាប់កំណត់អត្តសញ្ញាណរាល់សកម្មភាពទាំងអស់ក្នុង App។
  • នៅក្នុង ASP.NET Core: អនុវត្តតាមរយៈ Cookies (សម្រាប់ MVC Forms) ឬ JWT Bearer Token (សម្រាប់ Web APIs)។
២. Authorization (AuthZ) - "តើអ្នកមានសិទ្ធិធ្វើអ្វី?" (What can you do?)

និយមន័យ៖ គឺជាដំណើរការ ពិនិត្យនិងកំណត់សិទ្ធិ របស់ User ដែលបាន Authenticated រួចហើយ ថាតើគាត់មានសិទ្ធិមើល, បង្កើត (Create), កែប្រែ (Update), ឬលុប (Delete) ទិន្នន័យលើ Resource ណាមួយឡើយ។

ប្រយោជន៍សំខាន់ៗនៃ Authorization៖
  • រៀបចំឋានានុក្រមប្រើប្រាស់ (Role-Based Access Control - RBAC) ដូចជា `Admin`, `Manager`, `User`។
  • ការពារទិន្នន័យសំខាន់ៗ (Sensitive Data) មិនឱ្យ User ធម្មតាកែប្រែ ឬលុបដោយសេរីបានឡើយ។
  • នៅក្នុង ASP.NET Core: អនុវត្តតាមរយៈ Attribute [Authorize(Roles = "Admin")] លើ Controller ឬ Action Methods។

using System.ComponentModel.DataAnnotations;

namespace MyCodeFirstProject.Models
{
    public class AppUser
    {
        [Key]
        public int Id { get; set; }

        [Required(ErrorMessage = "សូមបញ្ចូលឈ្មោះពេញ")]
        [StringLength(100)]
        [Display(Name = "ឈ្មោះពេញ")]
        public string FullName { get; set; } = "";

        [Required(ErrorMessage = "សូមបញ្ចូល Email")]
        [EmailAddress]
        [StringLength(100)]
        public string Email { get; set; } = "";

        [Display(Name = "ស្ថានភាព")]
        public bool IsActive { get; set; } = true;
    }
}
២.២ File: `Data/ApplicationDbContext.cs` (Identity + Code-First)
តួនាទីរបស់ File: រួមបញ្ចូលគ្នារវាង ASP.NET Identity System Tables (AspNetUsers, AspNetRoles) និង Custom Entity Table (`AppUsers`) ចូលទៅក្នុង Database តែមួយ។
Data/ApplicationDbContext.cs
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;
using MyCodeFirstProject.Models;

namespace MyCodeFirstProject.Data
{
    public class ApplicationDbContext : IdentityDbContext
    {
        public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
            : base(options) { }

        // Code-First DbSet សម្រាប់តារាង AppUsers
        public DbSet<AppUser> AppUsers { get; set; }

        protected override void OnModelCreating(ModelBuilder builder)
        {
            base.OnModelCreating(builder);
            builder.Entity<AppUser>().HasIndex(u => u.Email).IsUnique();
        }
    }
}

[Route("api/[controller]")]
[ApiController]
public class AuthApiController : ControllerBase
{
    private readonly UserManager<IdentityUser> _userManager;
    private readonly IConfiguration _config;

    public AuthApiController(UserManager<IdentityUser> userManager, IConfiguration config)
    { _userManager = userManager; _config = config; }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginDto model)
    {
        var user = await _userManager.FindByEmailAsync(model.Email);
        if (user != null && await _userManager.CheckPasswordAsync(user, model.Password))
        {
            var claims = new List<Claim> {
                new Claim(ClaimTypes.Name, user.UserName!),
                new Claim(ClaimTypes.NameIdentifier, user.Id)
            };
            foreach (var role in await _userManager.GetRolesAsync(user))
                claims.Add(new Claim(ClaimTypes.Role, role));

            var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_config["Jwt:Key"]!));
            var token = new JwtSecurityToken(
                issuer: _config["Jwt:Issuer"], audience: _config["Jwt:Audience"],
                claims: claims, expires: DateTime.Now.AddHours(3),
                signingCredentials: new SigningCredentials(key, SecurityAlgorithms.HmacSha256)
            );

            return Ok(new TokenResponseDto {
                Token = new JwtSecurityTokenHandler().WriteToken(token), Expiration = token.ValidTo
            });
        }
        return Unauthorized("Email ឬ ពាក្យសម្ងាត់មិនត្រឹមត្រូវ");
    }
}

            var res = await _signInManager.PasswordSignInAsync(model.Email, model.Password, model.RememberMe, false);

    }

ជំហានទី ១៣: ការវិភាគប្រៀបធៀប Cookie-Auth VS JWT-Bearer Auth
4. Analyze
ការយល់ដឹងពីយន្តការសុវត្ថិភាពទាំងពីរគឺជារឿងសំខាន់បំផុតក្នុងការកសាងប្រព័ន្ធ Enterprise Hybrid Application (MVC + Web API)៖
លក្ខណៈវិនិច្ឆ័យ Cookie-Based Auth (MVC) JWT Bearer Auth (REST Web API)
ទីតាំងរក្សាទុក (Storage) HTTP Cookie ក្នុង Browser (HttpOnly, Secure) Client-side (LocalStorage, SessionStorage, Memory)
State Management Stateful / Session-based: Server រក្សា Session Stateless: Server មិនរក្សា Session ទេ (Token-self contained)
Header Format បញ្ជូនដោយស្វ័យប្រវត្តតាម Cookie: .AspNetCore.Cookies=... បញ្ជូនតាម Custom Header Authorization: Bearer <Token>
ហានិភ័យសុវត្ថិភាព (Risks) ងាយរងគ្រោះនឹង CSRF Attack (ត្រូវការ Anti-Forgery Token) ងាយរងគ្រោះនឹង XSS Attack ប្រសិនបកស្រាយ Token ខុសវិធី
ការប្រើប្រាស់ស័ក្តិសម Monolithic Web Applications, Server-Side Rendering (Razor) Mobile Apps, SPA Frameworks (React, Angular, Vue), Microservices

យុទ្ធសាស្ត្រការពារសុវត្ថិភាពទិន្នន័យ (Security Best Practices)

១. Token Expiration: ត្រូវកំណត់អាយុកាល Token ឱ្យខ្លី (ឧទាហរណ៍៖ ៣០នាទី ទៅ ៣ម៉ោង) ដើម្បីកាត់បន្ថយហានិភ័យពេលលេចធ្លាយ Token។
២. Secret Key Strength: Key ដែលប្រើក្នុង `appsettings.json` ត្រូវតែមានប្រវែងយ៉ាងតិច 32 characters (256 bits) ដើម្បីការពារ Brute Force Attack។
៣. Validate Anti-Forgery: ប្រើប្រាស់ [ValidateAntiForgeryToken] លើគ្រប់ POST/PUT/DELETE Actions ក្នុង MVC Controllers។

  1. EF Core Code-First អនុញ្ញាតឱ្យយើងបង្កើត Database ស្វ័យប្រវត្តិចេញពី C# Entity Models ដោយមិនបាច់សរសេរ SQL Command។
  2. JWT (JSON Web Token) ត្រូវការរក្សាទុក Session State នៅលើ Web Server ជានិច្ចដើម្បីផ្ទៀងផ្ទាត់ Identity។
  3. `IdentityDbContext` គឺជា Class ដែលមានស្រាប់ក្នុង ASP.NET Core Identity សម្រាប់បង្កើតតារាង User, Role, និង Claims។
  4. កូដ `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]` ប្រើសម្រាប់ការពារ API Endpoints ដោយតម្រូវឱ្យមាន JWT Token។
  5. Status code 200 OK គឺជា Response តែមួយគត់ដែលបញ្ជាក់ថា API Auth login ទទួលបានជោគជ័យ។

  • ១. មូលហេតុប្រើ Dual Auth Scheme: ដោយសារ MVC ដំណើរការតាមបែប Server-Side Rendering រក្សា State តាម Cookie និង Redirect ទៅ Login Page ពេលអត់ Auth, ចំណែក Web API ដំណើរការតាមបែប Stateless (Client-Server Decoupled) ទទួល JSON តាម HTTP Header Authorization Bearer និងបញ្ចេញ 401 Unauthorized ពេលអត់ Token។ ការដាក់ Dual Auth ធ្វើឱ្យ Framework ស្គាល់ Authenticate Scheme ទាំងពីរក្នុង App តែមួយ។
  • ២. LocalStorage VS HttpOnly Cookie: LocalStorage ងាយស្រួលប្រើប្រាស់ជាមួយ JS Fetch/Axios ប៉ុន្តែប្រឈមមុខនឹង XSS Attack ខ្ពស់ប្រសិន code មានចន្លោះប្រហោង។ ចំណែក HttpOnly Cookie ការពារ XSS បានល្អ (JS មើលមិនឃើញ) ប៉ុន្តែប្រឈមមុខនឹង CSRF Attack និងពិបាកកំណត់សិទ្ធិប្រើប្រាស់ Cross-Domain Mobile APIs។
